02 / HOW IT WORKS

Collect locally.
Investigate together.

Run the CLI on the source and the selected Linux subnet router for one explicit destination. Combine the bounded JSON bundles into an offline report with evidence links and a concrete next check.

No configuration changes or application requests. Collection makes diagnostic probes; analysis and export work offline.

Build and reproduce ↗
  1. CollectOS DNS, peer ping and explicit-IP TCP on the source; forwarding and direct TCP on the router.
  2. CorrelateMatch incident, destination, router identity and collection windows. Keep measured facts separate from hypotheses.
  3. ShareExport pseudonymized evidence and a standalone report. Topology, timing, platform and ports remain visible.

03 / WHAT THE DEMO ESTABLISHES

A controlled experiment, with visible limits.

Executed

Real Tailscale v1.104.1 daemons, Headscale 0.29.5 and a local DERP relay on one Docker host. The saved lab includes forwarding, DNS and TCP-refusal faults, each followed by recovery, plus an unprivileged LocalAPI check.

The five views above replay the forwarding experiment. The browser displays saved results; it does not run the probes.

Still unverified

Separate hosts and networks, the Tailscale service, native macOS daemon integration and IPv6 topology. Router selection is manual. The tool does not evaluate access policy, prove application health or inspect destination listeners.

The lab name comes from a hosts entry. QueryDNS fails even in the healthy control; this experiment does not validate MagicDNS.
